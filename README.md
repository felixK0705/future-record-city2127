# 100年後の街

> テーマ：「現代の課題を解決する為に100年後にあるもの」

2027年の街を、4分間だけ自由に歩く 3D 探索ゲームです。
プレイヤーに選択肢は一切示されません。街の中で何をしたか（歩いたか、ポッドに乗ったか、誰と話したか、ごみを拾ったか……）を裏側で静かに記録し、一日の終わりに「あなたの行動が創った100年後の街」を見せます。

どの行動にも正解・不正解はなく、どの一日もいずれかの未来につながっています。

## 遊び方

1. タイトル画面で「街へ出る」を押す
2. 街を自由に歩く（制限時間 4 分。中央の時計塔で鐘を鳴らすと早めに終えられる）
3. 時間が 2027 年から 2127 年へ跳ぶ
4. 100年後の街の姿（5種類の結末のいずれか）が現れる
5. 「あなたの足あと」で、影響の大きかった 3 つの行動と、それがつながった未来の物が明かされる

### 操作

| 操作 | パソコン | スマートフォン |
| --- | --- | --- |
| 歩く | WASD / 矢印キー | 左下のスティック |
| 走る | Shift を押しながら移動 | スティックを端まで倒す |
| 見回す | マウスでドラッグ | 画面をなぞる |
| 話す・拾う・乗る・使う | E キー | 右下のボタン |

## 街の5つの区域

| 区域 | ひそかに抱えている課題 |
| --- | --- |
| 住宅街 | 空き家の増加（空き家、ひとりで座るお年寄り） |
| 商店街 | 高齢者の孤立（シャッター街、バスを待つお年寄り） |
| 中央広場 | ヒートアイランド（照り返す日なたと、わずかな木陰） |
| 大通り | 交通渋滞（動かない車列、自動運転ポッドの乗り場） |
| 市場 | 食品ロスとごみ（散らばるごみ、売れ残り） |

## 困りごとと、その解き方

街には困っている人が4人います。選択肢は一切表示されませんが、同じ困りごとでも**どの方法で助けたか**によって、記録される行動（＝その人の価値観）が変わります。

| 困りごと | 自分の手で | AI端末から | 近くの人に頼む | シェアの道具 |
| --- | --- | --- | --- | --- |
| 住宅街：荷物が重くて家まで運べないお年寄り | 荷物を持って家まで一緒に歩く | 荷物運びロボットを呼ぶ | 近くの中学生に頼む | シェアカートを借りてくる |
| 市場：配達の箱を落とした会社員 | 散らばった箱を拾い集める | 運搬ロボットを呼ぶ | 市場の子どもに頼む | シェアカートを借りてくる |
| 商店街：バスが来なくて診療所に行けないお年寄り | 一緒に歩いて付き添う | 送迎ポッドを手配する | 豆腐屋の店主に頼む | — |
| 中央広場：暑さでふらふらしている子ども | 木かげへ連れていく | 冷却ミストドローンを呼ぶ | 木かげの会社員に頼む | — |

- **何もしないで通り過ぎた**場合も「通り過ぎた」として記録され、しばらくすると街の仕組み（ロボットやポッド）が代わりに解決します。あとから戻って助ければ、通り過ぎた記録は取り消されます。
- 解き方ごとの行動（`helpByHand` / `helpByRobot` / `helpByNeighbor` / `helpByShare` / `passTrouble`）は、それぞれ違う「100年後にあるもの」につながります。
- 荷物やカートを持っている間は走れず、ポッドにも乗れません。

## 必要な環境

- Node.js 20 以上（22 で動作確認）
- npm 10 以上

## インストール

```bash
npm install
```

## 開発サーバーの起動

```bash
npm run dev
```

ブラウザで表示された URL を開きます。開発モードでは起動時に `src/data/simulate.ts` が実行され、典型的な5種類のプレイヤー行動サンプルがどの結末になるかがコンソールに出力されます。

## 型チェック

```bash
npx tsc --noEmit
```

## ビルド

```bash
npm run build
```

`dist/` に静的ファイルが出力されます。Service Worker（`sw.js`）と `manifest.webmanifest` も同時に生成され、一度読み込めばオフラインでも遊べます（PWA としてホーム画面に追加可能）。

ビルド結果の確認：

```bash
npm run preview
```

## デプロイ

`dist/` フォルダの中身を任意の静的ホスティングにアップロードするだけで動作します。

- `vite.config.ts` の `base` は `'./'`（相対パス）なので、サブディレクトリへの配置でもそのまま動きます。
- Service Worker を有効にするため、HTTPS で配信してください（`localhost` は例外）。
- 例：GitHub Pages、Netlify、Vercel、Cloudflare Pages など。Netlify の場合は `dist` フォルダをドラッグ＆ドロップするだけで公開できます。

## 共有 URL

結末画面の「この未来を共有する」から、結果を再現する URL を共有できます。

```
https://example.com/?e=engawa&b=talkElder,helpNpc,walk
```

- `e`：結末の ID（`forest` / `optimized` / `engawa` / `sky` / `harmony`）
- `b`：影響の大きかった行動の ID（カンマ区切り、最大 3 つ）

この URL を開くと、タイトルを飛ばして「あなたの足あと」画面が直接表示されます。

## フォルダ構成

```
src/
  data/        内容の定義（ここだけを編集すれば調整できる）
    behaviors.ts  記録する行動・5つのパラメータへの重み・未来の物・説明文
    zones.ts      5つの区域の範囲と AI 端末の案内文
    npcs.ts       住人の配置と台詞
    troubles.ts   困りごと・解き方・台詞・道筋・シェアカート置き場
    endings.ts    5種類の結末と判定ロジック（純粋関数）
    simulate.ts   典型的な行動サンプルで結末の分布を確認する
  game/        ゲームの仕組み
    store.ts      zustand ストア（画面の状態と BehaviorLog）
    runtime.ts    毎フレーム変わる値（再レンダリングしない）
    tracker.ts    行動の検知（1秒ごとにストアへ同期）
    cityData.ts   街の配置の手続き的生成
    helping.ts    困りごとの進行（付き添い・拾い集め・ロボット・助っ人・シェア・通り過ぎ）
    interaction.ts / collision.ts / share.ts / constants.ts
  scene/       3D 描画（React Three Fiber）
    World.tsx City.tsx Player.tsx Npc.tsx Pod.tsx Litter.tsx FutureLayer.tsx Helping.tsx
  ui/          画面の部品と、それぞれの *.module.css
  styles/      global.css（リセットと CSS 変数のみ）
```

## 行動を追加・調整する方法

新しい行動の追加や重みの調整は、原則として `src/data/` の中だけで完結します。

### 重みを調整する

`src/data/behaviors.ts` の `BEHAVIORS` 配列で、各行動の `weights`（環境 / つながり / 経済 / テクノロジー / 自由）を書き換えます。

### 新しい行動を追加する

1. `BehaviorId` 型に新しい ID を追加する
2. `BEHAVIORS` 配列に定義を追加する
   ```ts
   {
     id: 'myBehavior',
     name: '日本語の行動名',
     weights: vec({ environment: 0.5, connection: 1.0 }),
     futureObject: { name: '100年後にあるもの', visual: 'helpBells' },
     revealText: '「あなたの足あと」画面に表示する説明文。',
     measure: (log) => countMeasure(log.aiUses, 3, log), // 0〜1 を返す
   },
   ```
3. `measure` は `BehaviorLog` から 0〜1 の強さを計算します。プレイ時間で正規化し、上限を設けてください（`countMeasure` / `zoneShare` などのヘルパーが使えます）。
4. 既存のログ項目で測れない行動の場合のみ、`BehaviorLog` に項目を追加し、`src/game/tracker.ts`（連続値）または `src/game/store.ts`（回数）で記録します。
5. `npm run dev` を起動し、コンソールのシミュレーション結果で5種類の結末すべてに到達できることを確認します。必要なら `src/data/simulate.ts` にサンプルを追加します。

### 困りごとを追加・調整する

`src/data/troubles.ts` の `TROUBLES` 配列に定義を追加します。

- `npcId`：困っている住人（`npcs.ts` に定義しておく）
- `request` / `explain` / `afterAmbient`：近づいたとき・話を聞いたとき・解決後のひとこと
- `route`：困っている人が目的地へ向かう道筋（最後の点が目的地。建物を通り抜けないよう、通りに沿って点を置く）
- `hand`：自分の手で助ける方法（`escort`＝一緒に目的地へ／`collect`＝散らばった物を拾い集める）
- `robot`：AI端末から呼ぶ乗り物（`robot` / `pod` / `drone`）とやって来る道筋
- `neighbor`（任意）：頼める住人と、その人が駆けつける道筋
- `share`（任意）：シェアカート置き場の ID（`SHARE_STATIONS` に定義）

解き方ごとの重みや未来の物は `behaviors.ts` の `helpByHand` などで調整できます。

### 結末の条件を調整する

`src/data/endings.ts` の定数で判定の傾向を変えられます。

- `MIN_TOTAL`：これ未満の合計値は「調和の街」
- `HARMONY_MARGIN`：1位と2位の差がこの割合未満なら「調和の街」
- `SKY_FACTOR`：経済と自由を合わせて「空へ広がる街」とする係数

### その他の定数

`src/game/constants.ts` で制限時間（`GAME_DURATION_SEC`）、歩く・走る速さ、ごみの判定半径などを変更できます。NPC の数の上限は `src/data/npcs.ts` の `MAX_NPCS` です。

## 技術スタック

- Vite + React + TypeScript
- Three.js（@react-three/fiber / @react-three/drei）
- zustand
- vite-plugin-pwa
- スタイルは CSS Modules のみ

3D の造形はすべて基本図形からプログラムで生成しており、外部のモデル・テクスチャ・フォント・CDN は使用していません。
